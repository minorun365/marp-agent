01

何が起きていたか

CDK の DockerImageAsset は、ビルドコンテキストに含まれるファイル群のフィンガープリントをそのままアセットハッシュにします。ハッシュが変わればイメージタグが変わり、CloudFormation は Lambda を置換します。

問題は、ビルドコンテキストがリポジトリのルート全体だったことです。infra/lib/ の TypeScript は Docker イメージの中身に一切関係しないのに、コンテキストの一部としてハッシュに算入されていました。

見落としやすいポイント：.dockerignore は「Dockerだけの設定」ではない

CDK の image-asset.js は、ソースディレクトリの .dockerignore を読んで、その中身を exclude プロパティとマージしてからフィンガープリントを計算します（exclude = [...dockerignoreの各行, ...props.exclude, '!.dockerignore']）。つまり .dockerignore への1行が、そのままアセットハッシュの入力を変えます。

infra/lib/web-stack.ts の fromImageAsset() には既にインラインの exclude 配列があり、docs / tests / infra/scripts などを除外していました。ただし infra/lib・infra/bin・tmp はどちらにも入っていませんでした。

02

変更内容（Before / After）

触ったファイルは .dockerignore 1本だけ、追加は4行です。infra/web/server.mjs は Dockerfile が COPY するので、ディレクトリ単位ではなく infra/bin・infra/lib・infra/scripts と細かく指定しています。

.dockerignore（末尾）
 amplify_outputs.json docs tests+tmp+infra/bin+infra/lib+infra/scripts

ビルドコンテキストへ実際にステージングされた infra/ 配下は、修正後は次の2ファイルだけになりました。Dockerfile の COPY infra/web/server.mjs は問題なく通ります。

  • infra/web/Dockerfile
  • infra/web/server.mjs

フロントのビルド（tsc -b && vite build）が参照するのは src/ と vite.config.ts だけで、tsconfig の include にも infra/ は入っていません。除外してもイメージのビルドには影響しないことを確認済みです。

04

この先の注意点

次のデプロイで1回だけ再ビルドが走る

除外を足したことでコンテキストの中身が変わるため、ハッシュは 3d6b8f67… → e62fb099… へ1回だけ移ります。この置換は避けられません。2回目以降、infra/lib だけを直したデプロイでは再ビルドが起きなくなります。

除外リストが2か所にあるので、片方だけ足さないよう注意

.dockerignore と web-stack.ts のインライン exclude は CDK 側でマージされるため、どちらへ書いても効きます。ただし現状は infra/scripts が両方、infra/lib は .dockerignore だけ、というふうに重複と偏りがあります。将来の除外追加でどちらか一方を見て判断すると取りこぼします。一本化する価値はありますが、今回は指示の範囲外なので触っていません。

.dockerignore にコメント行を足さない

ignoreMode が IgnoreMode.GLOB に設定されているため、CDK は各行を minimatch のパターンとして解釈します。Docker のコメント記法（# 始まり）が同じように扱われる保証がないので、現状どおりコメントなしのプレーンな一覧で保ちます。
