01

1件目：無言になる原因は3つ重なっていた

Kimiに切り替えてから出た症状で間違いありません。はみ出し検知のメッセージ自体がKimi専用の機能で、 それを入れたときに「検知したあとの待ち時間」を埋める仕組みだけが抜けていました。

① 検知メッセージがスピナーを止める

回っていた「スライドを作成中...」を「スライドを確認しました ✓」へ書き換える作りでした。 以降、次の output_slide が届くまで、動いている表示がゼロになります。

② 空白を埋めるはずの信号が捨てられていた

バックエンドは10秒ごとに {type:"progress", message:"処理中..."} を送っていました。 ところがフロントの振り分けに progress の分岐が無く、 受け皿は content と data しか見ないため、 message に入った文言が読まれず消えていました。

③ Kimiの「修正します。」も出ない

Kimiのテキストはいったんバッファに溜める作りで、Web検索を使った回は最後まで表示されません。 システムプロンプトで「修正します。の1文だけ出す」と指示していますが、その1文も画面に届いていませんでした。

なぜKimiだけか。 はみ出し検知メッセージ（slide_progress）はKimiのときしか送っていません （model_type != "kimi" なら送らない実装）。 Sonnetなどでは「スライドを作成中...」が最後まで回り続けるので、この空白が生まれませんでした。

該当箇所：useChatMessages.ts の appendSlideProgress、 agentCoreClient.ts の handleEvent、 agent.py のKimiテキストバッファ。

02

修正のBefore/After

画面の流れがどう変わるかです。修正はコミット済み・push済みですが、本番にはまだ反映していません。

BEFORE

🔄 スライドを作成中...
✓ スライドを確認しました
💬 文字や表のはみ出しを検知したので、スライドを修正します
（ここから数十秒〜数分、完全に無言）
🔄 スライドを作成中...
✓ スライドを作成しました

AFTER

🔄 スライドを作成中...
✓ スライドを確認しました
💬 文字や表のはみ出しを検知したので、スライドを修正します
🔄 スライドを修正中...（Tipsも回ります）
（そのまま継続。二重にステータスは出しません）
✓ スライドを作成しました

入れた変更

  • 検知メッセージの直後に「スライドを修正中...」を立てる。次の output_slide が届いてもステータスを重ねず、そのまま回し続ける
  • 待ち時間中もTipsをローテーションさせる（修正はスライド全文の作り直しなので長い）
  • 捨てられていた progress を拾い、message フィールドも読むようにする
  • 回帰テストを2本追加（検知後にスピナー付きステータスが1つ残ること、修正版が届いても1つのままであること）

テスト35件・リント・ビルドとも通過。コミットは 9550f4e と 6f592ce。

03

2件目：別テーマのスライドは再現できませんでした

本番と同じ設定（Kimi K2.5・同じシステムプロンプト・同じツール）をローカルで動かし、 考えられる3経路を試しました。結論としてどれも「Claude Code対Codex」を再現しません。 原因は未確定です。

試した経路想定した引きずり実際の結果
単発で投げる プロンプト自体が原因 正しくみのるん本人のスライドを生成（8枚）
前のスライドを文脈に付与 画面に残ったMarkdownが「現在のスライド」として渡る スライドを作らずテキストで回答して停止（別の不具合）
同一セッションの2ターン目 会話履歴に前のスライドが残る 「どう対応しますか？」と確認質問して停止（別の不具合）

構造としては、こういう経路があります

再現しなかっただけで、可能性が消えたわけではありません。とくに気になるのが1つ目です。

  • システムプロンプトにClaude CodeとCodexの固有指示が5行入っている。 8月12日のコミット e138f05（Kimiのスライド生成と根拠検証を改善）で追加されたもので、 「Claude CodeとCodexの比較では、まず site:support.anthropic.com ... を検索する」といった 実行可能な検索クエリまで名指しで書いてあります。全ユーザー共通のプロンプトに特定案件のチューニングが焼き込まれた状態です
  • 画面に前のスライドが残っていると文脈に入る。 セッションは15分アイドルで切れる仕様なので、しばらく放置して再開すると「現在のスライド」として前の全文が付きます
  • 同一セッションの会話履歴（直近6メッセージを保持）

他のユーザーとの混線ではありません。 AgentCore Runtimeはセッションごとに専用のマイクロVMで完全分離される仕様で、 公式ドキュメントでも「セッション終了時にVMごと破棄してメモリを消去する」と明記されています。 別の人の生成物がみのるんの画面に出る経路は、AWS側の作りとしてはありません。

04

そもそもログが残っていませんでした

2件目を追えなかった一番の理由がこれです。調査の副産物として見つかった、独立した問題でもあります。

コンテナのログが1行も出ていない

Dockerfileに PYTHONUNBUFFERED が無く、Pythonの print がバッファに溜まったまま CloudWatchへ流れていませんでした。出ていたのはライブラリ側のログだけです。 2時54分前後のログを引いても、コンテナの起動記録40行しかありませんでした。

Bedrock側のログも空

呼び出しログの設定自体は有効ですが、ロググループの最新レコードは2月6日で止まっています。 AgentCore経由の呼び出しは記録されていないようです。

対処として PYTHONUNBUFFERED=1 を入れ、実行開始時に 「セッションID・モデル・履歴の有無・プロンプト長・受け取ったMarkdown長」を残すようにしました。 プロンプト本文は出さず長さだけです。これを反映しておけば、次に同じことが起きたときは その回のセッションが何を受け取って動いたのかを後から確認できます。

05

次のアクションと、確認したいこと

デプロイの判断をお願いします

mainへpushしましたが、これだけでは本番は変わりません（CDKDの実行が別途必要）。 1件目の修正も、ログの修正も、反映して初めて効きます。 朝いちで npm run infra:diff から流してよければ進めます。

2件目について教えてほしいこと

  • 2時54分の直前に、Claude CodeとCodexを比較するスライドを作っていましたか？ 作っていた場合は「画面に残っていたものが引きずられた」線が濃くなります
  • そのとき画面には前のスライドが表示されていましたか、それとも新規で開いた状態でしたか
  • 出てきたスライドは、以前に自分で作ったものと同じ内容でしたか、それとも見覚えのない新しい内容でしたか

「見覚えのない新しい内容」だった場合は、システムプロンプトの焼き込みが効いた可能性が高くなります。 その場合はClaude Code／Codex固有の記述を汎用ルールへ書き換える修正を提案します。
